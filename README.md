## #96 グループ支払い・内訳ボタン（2026-10-31）

### 承認と対象
- #95を基準に実装。#95は利用者が実機で入力・履歴・カテゴリ集計の一致を確認済み。
- 利用者が内容と配置を確認し「それでよいです」「お願いします」と承認。Miniと別の共同精算アプリは変更しない。

### 記録画面とボタン
- 通常時の2段目は「やりとり／グループ／右端クリア」。1段目の支出・入金・資金移動・チャージ・設定ボタンは維持。
- やりとり中はグループ入口を隠し、従来の立替・清算・貸し借りを表示。
- グループ中はやりとり入口を隠し、左端にグループ、その右に会計・受け取った・支払ったを表示。
- 下の右側に控えめな細枠の「グループへ／個人へ」。個人とグループを直接切り替える。選択済みボタンの再押下で入口へ戻す案は採用しない。
- 上段の種類を選ぶと、やりとり・グループの入口が両方戻る。
- カテゴリ見出しのすぐ横に「＋ 内訳」。白背景・細いグレー枠・控えめな角丸・通常の文字太さ。右端配置と背景なし案は不採用。新規と編集の両方に反映。

### グループ会計
- グループ名、会計総額、自分が支払った額、自分の負担額を入力。金額はポイント利用前の円額。
- グループ名の入力候補は保存済み記録から生成。同じ名前を選ぶと同じグループへ記録する。全記録を削除したグループは候補にも残らない。
- 自分の支払がある場合は支払方法を選ぶ。0円なら支払方法不要。自分の負担がある場合だけカテゴリが必要。
- 参加者の内訳は任意の折りたたみ。必要な場合に他の参加者の名前・支払額・負担額を追加・削除できる。記入する場合は全参加者を入れ、自分と合算した支払額・負担額をそれぞれ会計総額へ合わせる。参加者名重複や合計不一致は保存前に拒否する。
- 会計ごとに清算相手を決める必要はない。他人同士の清算は個人の貸し借りへ計上しない。
- 自分の支払・負担が両方0円の参考会計も保存できる（総額は1円以上）。自分の残高・支出・グループ差額は変化しない。
- 自分の負担分だけカテゴリ分割。ポイントは支払額・負担額の両方を超えない。実際の支払と支出集計の両方から同じポイント数を控除。カテゴリへの配分は#95の比例配分。
- 引落時割引と分割回数はカード請求へ反映。支出集計から引落時割引をさらに控除しない。
- 特別費イベントにも関連付け可能。特別費と清算グループは別の情報として保持する。

### 金額の反映と清算
- グループ差額＝自分の支払（ポイント前）−自分の負担（ポイント前）−受取額＋清算支払額。
- 差額が正なら「受取残額」、負なら「支払残額」、0なら「清算済み」。ポイントの控除で差額は変えない。
- 例：総額9000、自分の支払9000、負担3000、ポイント300の場合、現金支払・カード請求は8700、自分の支出2700、グループ受取残額6000。
- 清算はグループ名・相手・金額・実際に動く口座/現金/チャージ残高で記録。会計ごとの割当不要。カード決済は清算時の口座残高移動とは別なので清算の選択対象外。
- 受取は受取先残高を増やし、支払は支払元残高を減らす。通常の収入・支出へ再計上しない。清算時の手数料追加は今回の対象外。
- 個人別の貸し借り残高・相手候補にはグループ記録を含めない。
- 後から会計を追加できる。清算後に漏れた会計や編集・削除で差額が生じたら再び未清算として扱う。

### 閲覧と編集
- 貸し借り画面に「個人／グループ」の切り替え。グループカードは名前・差額を表示し、展開すると会計・清算履歴、任意の参加者内訳、編集・削除、記録への入口がある。
- 記録履歴の「やりとり」フィルタでもグループ記録を表示。グループ名・相手・メモで検索できる。
- ホームのやることリストは差額が残るグループにつき1件、強調した「✓ グループ名：受取残額/支払残額」を自動表示。詳細でグループカードへ移動。差額0で自動的に消える。手動完了で清算済みにはしない。
- 記録単位で編集できる。グループ名を別名へ変更するとその記録を別グループへ移す（グループ全体の一括改名機能ではない）。
- 編集時は全項目の検証後に元の効果を取り消し、新しい内容を反映。不正入力なら元の記録・残高を維持。削除も支払効果を戻し差額と請求を再計算。

### 保存と確認
- 保存形式6。形式2〜5を読み込み可能。既存データの初期化・一括金額修正を行わない。
- 内部では既存の立替・受取・返済データにgroupId/groupNameを加え、グループ会計にはgroupTotal（会計総額）、gross（自分の支払額）、amount（自分の負担額）、groupParticipantsを保持。個人の履歴をまとめる既存loanGroupsとは別。
- 再読み込み・JSON書き出し・新しい環境への復元でグループと内訳を保持し、復元時も形式・金額・内訳を検証。
- 更新ファイルに版番号を付けて読み込み、古い処理ファイルが使われる可能性を減らす。
- #96保存後は#95以前の旧版へ戻さない。更新前にバックアップを保存。#96も実データ入力禁止。
- ダミーデータの自動検証：入口/切り替え、複数カテゴリ/ポイント、現金/カード、個人への非計上、清算の追加/編集/削除、他人払い、複数支払者の内訳、0円参考会計、特別費集計、不正金額拒否、やること、再読み込み/バックアップ復元、旧版拒否。
- 既存のポイント23項目・金融計算202比較・メモ操作・#95の複数カテゴリ/日付境界の回帰検査。画面幅360/390/412pxで確認。スマホ実機はこれから確認。
