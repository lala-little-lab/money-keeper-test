## #95 複数カテゴリ・起動時の現地日付（2026-10-31）

### 範囲と承認
- 基準：ユーザーが導入を確認した本体#94。第1段階「複数カテゴリ対応＋現地日付修正」の実装案提示後、利用上限による中断を経て「再開で」と依頼を受けて実装。
- Miniは変更しない。グループ会計・まとめ清算・外貨対応は今回未実装。

### 入力・自動計算
- 支出、私が立替、相手が立替のカテゴリ欄に「＋ 内訳を追加」。普段は従来の単一カテゴリ入力。
- 複数カテゴリの対象額は支出の購入額、立替では自分の負担額（ポイント利用前）。相手の負担分は分割対象外。
- 内訳は2件以上。同じカテゴリの重複、未選択、不正金額、合計不一致を拒否。0円内訳は許可する。
- 未入力の金額欄が1つだけなら、対象額から手入力分を引いた残りを自動表示。「自動」と明示する。手入力した金額は変更しない。
- 自動表示した欄も直接編集できる。直接入力した後は手入力額として維持。空欄にすると再び自動計算の候補になる。
- 自動額が表示されている状態で行を追加する際は、既存の表示額を確定値として維持し、新行を追加する。自動欄を含めて金額が勝手に減ることを防ぐ。
- 例：合計3000／食材2000／日用品1000へ、お菓子300を追加したら300円超過を表示し保存しない。利用者が内訳または合計を直す。
- 行削除で1カテゴリに戻ると、従来の単一カテゴリ方式に戻る。そのカテゴリへ対象額全体を割り当てる。
- 保存後の編集では内訳を確定金額として読み込む。合計だけ変更しても内訳を勝手に変更せず、不一致を確認する。

### ポイントと集計
- 使用ポイントを各内訳の購入額に比例配分。整数演算で切り捨てた後、小数部が大きい順に1ptずつ付与し、配分合計を一致させる。同率は表示順で決定。
- 自分の負担分を超える立替ポイントは既存仕様どおり拒否。全額ポイント、自分の負担0円にも対応。
- 例：食材2000・日用品1000／300ptは200pt・100ptに配分し、集計は1800円・900円。
- 月別総額、カテゴリ別予算・推移、特別費のカテゴリ別集計へ反映。手数料は既存の別カテゴリ計上を維持。引落時割引を追加で支出集計から控除しない。
- 会計は1件を維持。残高・カード請求・相手への貸し借りは既存の会計全体の処理を維持し、カテゴリごとに二重計上しない。
- 履歴・最近の記録・特別費一覧の共通説明にカテゴリ別のポイント控除後金額を表示。カテゴリ検索・絞り込みは内訳の各カテゴリに一致する。主額は会計全体で、内訳額と区別する。
- メモの関連候補は選択した複数カテゴリを対象とし、既存の候補順を保って重複せず表示する。

### 日付
- 起動時は端末の現地日付を設定。従来のUTC由来の前日表示を解消。リセット時の既存仕様と統一。
- 保存済み日付を変更せず、日付をまたいで開き続けたフォームの自動更新は追加しない。

### 保存・互換性
- 記録にcategorySplits:[{category,amount}]を追加。従来のcategoryは先頭カテゴリとして保持。ポイント配分は保存した内訳と使用ポイントから一貫したルールで再計算。
- 保存形式は5。設定入りの形式2・3・4を読み込み可能。既存記録を自動分割しない。形式1の取り込み制限は従来どおり。
- 新しい内訳のカテゴリ・金額・合計・ポイントを読込み時、復元時に検証。不正な内訳を読み込まない。
- #95保存後は#94以前のアプリが新形式を拒否する。旧版を再アップロードせず、修正は#95を基準に進める。
- 更新前のバックアップを保存。端末データの初期化、既存カード設定の変更、Miniへの上書きはしない。

### カードの追加
- 「カード・引落」の＋追加から、カード名・締め日（1〜31日または月末）・引落日（翌月1〜31日）・登録済み銀行口座を指定。
- カード名は1〜60文字、空欄／< >／制御文字／既存支払方法と同じ名前を拒否。重複は全角半角・空白・大文字小文字を正規化して比較。
- 引落口座は銀行口座から選ぶ。現金・プリペイド残高は対象外。銀行が未登録なら先に口座・残高で追加し、同じ設定の下書き内でも選べる。
- 「設定に追加」で下書きに追加。最後の「保存」で一括反映。追加フォームを戻っても入力を保持し、設定トップから保存した場合も変更済み入力を検証する。
- 新カードは支払方法の「もっと見る」末尾の新しい行に追加。既存の並びは動かさない。カード請求一覧にも追加し、支出・私が立替・ポイント差引後の請求金額・分割回数に対応。
- 新カードの開始時点の請求額は0。過去利用分を自動生成しない。カードからのチャージ等の計算経路自体は共通だが、新カードをチャージ元・楽天Pay支払元・定期支払い元の候補へ無条件に追加しない。サービスごとの対応可否を設定する画面は今回対象外。

### 既存カードの編集と適用月
- 登録済みカードの締め日・引落日・引落口座は、そのまま引き継ぐ。#94導入時に一律変更しない。
- カード名だけの変更では適用月を要求せず、同じ内部IDの表示名を更新。過去の取引を書き換えない。
- 日付・口座を実際に変更したときだけ「変更を適用する引落月」を表示する。指定するのは購入月ではなく、引落がある月。
- 変更履歴をカード設定のschedulesに追記する。元の設定を残し、対象月より前には元の設定を使う。
- 適用月は当月以降、かつ確定・調整済み請求、引落済み、手動で請求月を移した記録、請求明細金額調整、既存の設定変更履歴の後の月を選ぶ。保護対象月を選ぶと反映前に止める。
- 予定請求の再配分は、従来の引落月が適用月以降になる記録に新しい締め日を適用。新計算で適用月より前へ戻る場合は適用月に収める。対象の予定請求額・月が変わることはある。購入日・カテゴリの支出額は変えない。
- 分割の次回以降は、その引落月の設定日を使用。存在しない日付（2月31日等）はその月の末日。金融機関の休業日繰延の自動判定は今回追加しない。
- 引落の残高反映・入金準備の案内は対象月の引落口座を参照。引落取消は引落時に保存した口座・金額を戻す。
- カード削除・設定履歴の削除／取消は今回対象外。
