## #94 共通設定への入口・配置タブ・カード追加編集（2026-10-30）

### 今回の確定仕様
- 基準は本体テスト版#93。#93はユーザーがダウンロード・導入済み、戻る操作の改善を実機で確認。Miniとは別プロジェクト。
- ホーム残高横に加え、記録画面のチャージボタン右横にも同じ線画の歯車を置く。どちらからも「口座・残高／支払方法／カード・引落／ボタン配置」の4枚を開く。
- 「その他」には入口を追加しない。引落タブへの入口も今回は見送り。設定はお金を置く・動かす手段の管理として共通化する。
- 記録途中の金額・メモ・選択を保って設定を開閉する。設定内の戻る、保存前の下書き、閉じる際の破棄確認は#93を継承。
- ボタン配置は「支払方法／入金先／チャージ元」の3タブ。選択した範囲だけ表示し、タブ切替中も編集中の配置を保持する。タブ切替は設定内の階層移動には数えない。
- 支払方法内は上が「いつも表示」、下が「もっと見る」のまま。別タブ化しない。プレビュー、行ごとの1〜4個、右つまみの順番変更、両枠間の移動を維持する。

### カードの追加
- 「カード・引落」の＋追加から、カード名・締め日（1〜31日または月末）・引落日（翌月1〜31日）・登録済み銀行口座を指定。
- カード名は1〜60文字、空欄／< >／制御文字／既存支払方法と同じ名前を拒否。重複は全角半角・空白・大文字小文字を正規化して比較。
- 引落口座は銀行口座から選ぶ。現金・プリペイド残高は対象外。銀行が未登録なら先に口座・残高で追加し、同じ設定の下書き内でも選べる。
- 「設定に追加」で下書きに追加。最後の「保存」で一括反映。追加フォームを戻っても入力を保持し、設定トップから保存した場合も変更済み入力を検証する。
- 新カードは支払方法の「もっと見る」末尾の新しい行に追加。既存の並びは動かさない。カード請求一覧にも追加し、支出・私が立替・ポイント差引後の請求金額・分割回数に対応。
- 新カードの開始時点の請求額は0。過去利用分を自動生成しない。カードからのチャージ等の計算経路自体は共通だが、新カードをチャージ元・楽天Pay支払元・定期支払い元の候補へ無条件に追加しない。サービスごとの対応可否を設定する画面は今回対象外。

### 既存カードの編集と適用月
- 登録済みカードの締め日・引落日・引落口座は、そのまま引き継ぐ。#94導入時に一律変更しない。
- カード名だけの変更では適用月を要求せず、同じ内部IDの表示名を更新。過去の取引を書き換えない。
- 日付・口座を実際に変更したときだけ「変更を適用する引落月」を表示する。指定するのは購入月ではなく、引落がある月。
- 変更履歴をカード設定のschedulesに追記する。元の設定を残し、対象月より前には元の設定を使う。
- 適用月は当月以降、かつ確定・調整済み請求、引落済み、手動で請求月を移した記録、請求明細金額調整、既存の設定変更履歴の後の月を選ぶ。保護対象月を選ぶと反映前に止める。
- 予定請求の再配分は、従来の引落月が適用月以降になる記録に新しい締め日を適用。新計算で適用月より前へ戻る場合は適用月に収める。対象の予定請求額・月が変わることはある。購入日・カテゴリの支出額は変えない。
- 分割の次回以降は、その引落月の設定日を使用。存在しない日付（2月31日等）はその月の末日。金融機関の休業日繰延の自動判定は今回追加しない。
- 引落の残高反映・入金準備の案内は対象月の引落口座を参照。引落取消は引落時に保存した口座・金額を戻す。
- カード削除・設定履歴の削除／取消は今回対象外。

### 記録開始日の相談と切り分け
ユーザーは11月1日から記録開始を希望。必要なNZ旅行費などのみ遡及入力する方針。これとカード設定の変更開始月は別の話であり、「全カードを11月から変更」の案は撤回。今回、既存カードの設定自体は変更しない。開始時残高と開始前のカード利用・引落済み支出の導入手順は別途整理する。実データ入力禁止表示は維持。

Miniへの共有希望はあるが、この版でMiniのコード・保存データは変更していない。共通仕様の共有は実装差分を確認して別途行う。
