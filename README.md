## #93 設定の戻る操作と口座・電子マネー追加（2026-10-30）

基準：本体#92。対象ZIP：MK_test_093_261030_Account_Add.zip。Mini・共有精算アプリは別管理。

### 今回の承認範囲
#92の画面調整と、②銀行口座・チャージ式電子マネーの追加を同じ版で実装。カードの追加・締め日や引落口座の変更、削除は今後の③等で検討する。

### 設定画面の整理
- ホーム「残高」横の歯車は、同じサイズ・位置で左右対称の8歯の線画に変更。
- スマホ／ブラウザの戻る操作で、編集・追加画面→一覧→4カードの設定トップ→元の画面へ戻る。画面内の「設定一覧へ」「戻る」リンクは設けない。
- タイトルを「口座・残高」「支払方法」「カード・引落」「ボタン配置」等に切り替え、現在地を示す。
- 設定トップ・一覧上部の説明文と並べ替え説明を削除。口座の非表示でも合計・引落に含む説明は、編集画面の切り替え直下に短く配置。
- 確認専用「カード・引落」では保存ボタンとその余白を非表示。カード名は引き続き支払方法から編集可能。
- 編集欄の文字・表示切り替え、追加フォームの入力は、設定内で戻っても保持。再度開くと続きから編集できる。
- 「設定に反映」「設定に追加」は下書きに反映して一覧へ戻る操作。端末への反映は最後の「保存」。入力後に戻って設定トップから保存した場合も、保持した未反映入力を検査して保存する。追加フォームが初期状態のままなら追加しない。
- 編集画面の「編集を戻す」はその項目の未反映入力を破棄する操作。
- 設定全体を閉じるときだけ、未保存の変更があれば破棄確認。戻る／キャンセルで閉じる場合とも同じ。確認を取り消すと入力を保持して設定に残る。変更がなければ確認せず閉じる。保存成功後も確認不要。
- 閉じた後にブラウザの進む操作をしても、破棄した下書きを復活させない。

### 追加フォーム
「口座・残高」の〔＋追加〕から設定する。

|項目|銀行口座|チャージ式電子マネー|
|---|---|---|
|種類|銀行口座|チャージ式電子マネー|
|名前|1〜60文字|同左|
|ボタンの表示名|任意。空欄なら名前と同じ|同左|
|現在の残高|初期値0円。整数、±999,999,999円以内|初期値0円。0〜999,999,999円の整数|
|いつものチャージ元|入力なし|登録済みの表示中のチャージ元から選択必須|

前後の空白を除去。同名は正規化して重複を拒否。< >・制御文字・小数・不正金額を拒否。項目数上限は口座・支払方法それぞれ200。追加内容は保存前まで下書きとし、キャンセル時は開始残高も登録しない。

### 反映先と配置
- 銀行口座：ホーム残高、残高合わせ、入金先、資金移動元・先、直接支払う支払方法、チャージ元。
- 電子マネー：ホーム残高、残高合わせ、支払方法、チャージ先。残高として登録するため、従来の残高一覧を使う資金移動候補にも表示される。
- 電子マネー支払いは、その残高からポイント等を引いた実支払額を減らす。チャージは従来どおり資金移動扱い。カードからのチャージは該当カードの請求対象となる。
- 開始残高は支出・収入・カテゴリ・特別費として集計しない。取引や通帳の入出金を作らず、その時点の残高として設定する。
- 新規支払方法は「もっと見る」の末尾に新しい行で追加。銀行の入金先・チャージ元も末尾の新しい行に追加し、既存の行と並びを動かさない。後からボタン配置で行構成を変更できる。
- 元からある楽天Edyは現在の支払ボタン位置を維持する。
- 追加した銀行を、まだ保存していない同じ設定作業中でも、新しい電子マネーのチャージ元に指定できる。
- 新規銀行を既存カードの引落口座へ付け替える操作は未実装。定期支払いの新しい経路設定の完成も対象外。既存の経路・請求設定はそのまま。

### 既存の楽天Edyに残高管理を追加
- 電子マネー選択時、未管理の楽天Edyがあれば「楽天Edyに残高を追加」を選べる。表示名は既存設定から取得。
- 新規電子マネーとして同じ楽天Edy名を入力した場合も、既存の内部IDを利用して重複を防ぐ。
- 入力した現在残高から管理を開始。過去の記録・金額・集計・貸し借りを再計算しない。Edyの支払方法をもう1つ作らない。
- 残高管理開始前のEdy関連記録IDを、口座設定のuntrackedTxIdsに保持する。これらの記録のEdyへの残高反映は編集・削除時も行わず、開始残高がずれることを防ぐ。既存取引の内容自体は書き換えない。
- 管理開始後の新規Edy記録は通常どおり残高へ反映し、編集・削除の差分も反映する。
- 過去の記録が識別できない場合は、推測せず追加を止める。
- Edyの残高はユーザーが入力する。過去に話題となった金額を固定の初期値として埋め込まない。

### 保存・互換性
- 保存形式schemaVersionを3に更新。口座種別kindと、必要な場合のuntrackedTxIdsを保持する。設定versionは1、UI設定は従来どおり。
- #89〜#92の設定入りschemaVersion 2を読み込める。既存データ・金額を再計算せず、新形式で保存する。schemaVersion 1は引き続き非対応。
- 新形式に対応しない旧版は読み込みを拒否するため、旧処理で管理開始前の記録を再計算しない。新しい版で運用する。旧バックアップを残すために旧版を再アップロードする必要はない。
- 追加設定・開始後残高・管理開始前の記録ID・配置・表示設定はJSONバックアップで維持。名前はMK_YYYYMMDD_HHmmss.json。イベント固定ON/OFFの従来の別保存範囲は変更しない。
- 設定と開始残高を同一の保存処理で反映。保存失敗時は既存の端末データと表示上の残高を維持し、下書きから再試行できる。
