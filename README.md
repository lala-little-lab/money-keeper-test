# Money Keeper 本体テスト版 #91

## #91 保存済み設定だけで起動する版（2026-10-29）

基準：本体#90。対象ZIP：MK_test_091_261029_Saved_Settings.zip。Miniは別管理。

### 実装した範囲
- 個人用の口座一覧、支払方法一覧、カード締め日・引落日・引落口座、チャージ既定元、ボタンの行構成等を生成する初期テンプレートをアプリから除去。
- 起動時は端末のmkSettingsを読み込む。設定から口座・カード・候補・表示名を構成し、既存の内部ID、残高、取引、請求確定、引落済み、貸し借りを引き継ぐ。取引を再実行して残高を作り直さない。
- 設定検査を固定テンプレートとの一致判定から、形式・IDの重複・参照先・配置内の重複と欠落・残高との対応・請求先と引落済み口座の整合判定へ変更。
- 現行の残高処理は同一IDへの直接反映を前提とするため、balanceRoutesの別IDへの付け替えは拒否。任意の支払元変更・カード新規追加・過去記録の再配分を実装したものではない。
- 楽天Payの支払元ボタン、説明、定期支払いの支払元候補も保存設定から描画。一般的な決済サービスの識別子と対応処理は残す。
- 起動時は設定を検査し、画面準備ができるまで通常画面を操作できない。保存済み設定がない場合は初期データを作らず、バックアップ復元案内を表示。空データを自動保存しない。
- 保存内容が壊れている場合も、元データを上書きせず復元案内を表示する。復元は検証とユーザー確認の後に全置換する。キャンセル・検証失敗・保存失敗時は既存保存内容を維持する。
- ストレージが利用できない場合は案内を出して復元ボタンを無効にする。

### バックアップと互換性
schemaVersionは2、mkSettings.versionは1のまま。#89・#90で保存した設定入りJSONを復元できる。ファイル名が以前の長い名前でもよい。
#88以前のschemaVersion 1は設定が含まれないため、#91では拒否して案内する。欠けた設定を推測して再生成しない。
ファイル名は#90の `MK_YYYYMMDD_HHmmss.json` を維持（端末の現地日時、秒まで）。イベントの「ONで固定」は従来どおり別のlocalStorage保存で、JSONバックアップ対象外。この制限は今回変更していない。

### 更新時の手順
1. 更新前に、設定入りバックアップを保存して残す。
2. アプリ7ファイルを一式差し替える。資料ZIPはGitHubへアップロード不要。
3. いつもの同じブラウザで開き、上部の#91表示・残高・記録・支払方法の並び・カード請求が今までどおりであることを確認する。通常は復元操作不要。
4. 再読み込み後にも維持されることを確認する。
5. いつものブラウザなのに復元案内が出た場合は、すぐに上書き復元せず、表示メッセージとブラウザを確認する。新端末・別ブラウザの場合は、保存してある設定入りJSONで復元する。

⚠️ #88以前はアップロードし直さないでください。

### 確認したこと
- JS構文確認。#90→#91の起動で全保存項目が一致し、再読み込みでも維持。
- 支出・入金・移動・チャージ・やりとり6種の候補文字列、ボタン座標・寸法、カード経路・日付・請求表示を#90と比較して一致。
- ダミーデータの残高処理202ケースを#90と比較して一致。ポイント関連23項目と再読み込み、メモ候補・クリア／戻す・スクロール等も確認。
- 空のブラウザ環境では保存データを作らず、明示的な復元から起動できる。通常環境・空環境それぞれで12種の不正バックアップを拒否し、DBが変わらないことを確認。
- 取込みキャンセル、保存失敗、壊れたDBからの復元、ストレージ利用不可、短い日時付きの再書出しを確認。
- ユーザー添付の#89 JSONは読込み検証のみ行い、適合を確認。個人データを動作テスト環境へ復元していない。
- #91のユーザーのスマホ実機確認はこれから。全機能・全端末の試験完了ではない。実データ入力禁止のテスト版を維持。
